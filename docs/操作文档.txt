一、包目录说明
--------------------------------------------------------
QQBot-Pack\
├─ 首次配置.bat         一键首次配置：检查 Node → 生成 config\bridge.config.json
│                       （从模板复制）→ 在 app\dsh 里 npm 安装 DSH（联网一次）
├─ 启动全部.bat         一键启动：NapCat → DSH → 管理台 → 等 3001 → 桥接 → 开浏览器
├─ 停止全部.bat         一键停止：按窗口/进程特征结束 NapCat/DSH/桥接/管理台
├─ 启动桥接.bat         只启动桥接（带 5 秒自动重启循环）
├─ README.txt           面向新手的快速上手（先看这个）
├─ persona\
│   └─ 我的机器人.txt    人设档案模板：改成你自己的设定（名字/性格/语气…）
│                       改完删掉旧 AI 会话后自动重新播种生效
├─ config\
│   └─ bridge.config.example.json   配置模板（全部留白 + 逐字段中文说明）
│       首次配置.bat 会把它复制成 bridge.config.json 供你填写
├─ docs\
│   └─ 操作文档.txt      本文件
├─ logs\                （运行后生成）bridge.log / dsh.log / webui.log
├─ tools\               （预留，放辅助小工具）
└─ app\
   ├─ napcat\            NapCat（QQ 协议端，单进程修复版）
   │   ├─ node-bundle\      NapCat 运行内核（node.exe + wrapper.node + DLL 全家桶）
   │   │                    拷到新机器即用，无需安装
   │   ├─ data\             NapCat 运行时数据（config/cache/logs，首次登录后自动生成
   │   │                     每账号配置，如 napcat_你的QQ号.json、onebot11_你的QQ号.json）
   │   ├─ 启动NapCat.bat            单进程启动器（默认二维码登录，带自动重启循环）
   │   └─ 启动NapCat-账密回退.bat   同左，附账密回退模板（默认不启用，需自己填）
   ├─ dsh\                DeepSeek Harness（AI 服务）
   │   ├─ package.json        依赖 @deepseek-ai/dsh（版本固定，首次配置时 npm 安装）
   │   ├─ node_modules\       （首次配置后生成，装完即可离线运行）
   │   ├─ home\               DSH 本地数据根目录（DSH_HOME）
   │   │   ├─ profiles\web\        web profile（首次启动自动生成，含插件装配清单）
   │   │   └─ .credentials.yaml    （你填的 DeepSeek API Key 存这里）
   │   └─ 启动DSH.bat         DSH 启动器（自动重启循环，日志另见 logs\dsh.log）
   ├─ bridge\            桥接程序（QQ ↔ DSH 中间人，Node 22+ 零 npm 依赖）
   │   ├─ bridge.mjs          主程序（触发判定/限频/人设播种/看门狗/日志落盘）
   │   ├─ dsh-client.mjs      DSH 本地 API 客户端（取回复等公共逻辑）
   │   └─ 启动桥接.bat（根目录同款）— 桥接由根目录 启动桥接.bat 拉起
   └─ webui\             门户 + 管理台（Node 22+ 零 npm 依赖 http 服务，端口 3210）
       ├─ server.mjs          服务端（状态探测/配置读写带备份/日志/重启指令）
       └─ public\index.html   单页界面（中文、默认蓝色系）

二、端口表
--------------------------------------------------------
  端口  归属                用途                               谁连谁
  ----  ------------------  ---------------------------------  -------------------
  6099  NapCat WebUI       QQ 小号扫码登录、NapCat 后台管理    浏览器访问
  3001  OneBot WS(正向)    NapCat 把群消息推给桥接             桥接连接
  3080  DSH Web/API        AI 控制台(填 Key/看会话) + 本地 API  浏览器 + 桥接
  3210  QQBot 管理台       本包门户 + 管理面板                  浏览器访问
  34567 bridge 单实例锁    防止两个桥接同时跑重复回复           桥接自占

  注意：全部只绑定 127.0.0.1（本机回环），不对外网开放。
  若某个端口被别的程序占用，服务会起不来——先 netstat -ano | findstr "端口" 看是谁占了。

三、配置详解：config\bridge.config.json
--------------------------------------------------------
首次配置.bat 会从 bridge.config.example.json 复制生成。文件里每个字段附近都有
"_说明"文字（下划线开头 = 纯说明，程序不读，可留可删）。这里再挑重点讲：

  bot.name            机器人的名字。会写进给 AI 的身份描述里。留空默认"小助手"。
  owner.qq / owner.nick  主人 QQ 号 / 昵称。只有这个 QQ 会被 AI 当主人对待。
                      留空则 AI 对所有人都按普通群友对待。
  onebot.wsUrl        NapCat 正向 WebSocket 地址。默认 ws://127.0.0.1:3001，
                      与 NapCat 的 onebot11 配置一致就不用改。
  onebot.accessToken  NapCat 网络配置里设了 token 才需要填，没设留空。
  onebot.selfId       你的小号 QQ 号。留空时桥接会自动从消息事件里识别（推荐留空）。
  dsh.baseUrl         DSH 地址。默认 http://127.0.0.1:3080 不用改。
  dsh.sessionId        AI 会话名前缀。每个群自动拼成 "前缀-群号"，一群一会话、
                      记忆互相隔离。建议改成你自己的标识（如 my-bot）。
  dsh.cwd             AI 会话的工作目录。留空 = 封装包根目录（推荐留空，绿色可移植）。
  groups              群白名单（重要）：机器人只在列出的群里回复。
                      格式：[群号1, 群号2]，同一个方括号、逗号分隔。
                      留空 = 机器人在任何群都不说话（不工作，先填它！）。
  personaFile         人设档案路径，相对包根。默认 persona\我的机器人.txt。
                      桥接在【新建 AI 会话】时读取该文件全文作为人设种子；
                      会话建好后改文件不影响旧会话（删掉旧会话或换 sessionId 即重生）。
  seedExtra           附加播种文本（可选）：追加在人设之后的一段补充指令。
  replyPolicy.interestKeywords  兴趣词：群里出现这些词且没被 @ 时，机器人才会
                      考虑主动插嘴（要不要插嘴由 AI 结合上下文判断）。
  replyPolicy.blockKeywords     黑名单词：出现这些词必静默（强烈建议保留
                      转账/密码/验证码/银行卡/红包这类金钱隐私词）。
  replyPolicy.silentMarker      AI 的"沉默暗号"。AI 觉得不该说话时回这个词，
                      桥接拦截不发。默认 [SILENT]。
  replyPolicy.contextWindow     喂给 AI 的最近群消息条数（默认 8）。
  replyPolicy.maxRepliesPerMinute 限频：每分钟最多回几条（默认 3，防风控）。
  replyPolicy.replyAt           被 @ 时是否 @ 回去（默认 true）。
  replyPolicy.fallbackText      AI 卡住/超时兜底提醒文案（只发给 @ 你的人）。
  replyPolicy.rules   每次发问前附带的规则文本（管理台可热改）。支持占位符：
                      {botName} {selfQq} {ownerNick} {ownerQq}，程序发问前自动
                      替换成实际值——所以里面不要写死 QQ 号。
  timeouts.replyMs     等 AI 回复的超时毫秒（默认 300000 = 5 分钟）。
  timeouts.pollMs      轮询 AI 回复的间隔毫秒（默认 1200）。
  watchdog.enable      掉号看门狗开关（默认 true）。见第五节。
  watchdog.pingIntervalMs  探活间隔毫秒（默认 30000 = 30 秒）。
  watchdog.missLimit   连续探活失败多少次判定掉号（默认 3）。
  watchdog.reloginMinGapMs  两次自动重登最小间隔（默认 300000，防抖）。
  watchdog.maxRelogin  连续自动重登上限（默认 3，防风控，超限停下提示人工）。
  watchdog.launcherBat 重登时启动的 NapCat 启动器文件名（须放在 app\napcat 下，
                      默认 启动NapCat.bat；想用账密回退就改成
                      启动NapCat-账密回退.bat 并先去里面填好账号密码）。

  改配置=热生效：bridge 每条消息前会重读配置文件，保存即生效，无需重启。
  管理台"管理面板"也能改上面大部分内容，保存效果一样（写前自动备份 .bak）。

四、登录引导（QQ 小号 / 换机 / 掉线）
--------------------------------------------------------
4.1 首次登录（扫码）
  1) 启动全部.bat 后，NapCat 窗口出现，服务就绪；
  2) 打开 http://127.0.0.1:6099/webui —— 管理台门户上有"打开(带令牌)"按钮，
     自动带上令牌省得手输；
  3) 页面上出现二维码 → 用【你的 QQ 小号】手机 QQ 扫码确认；
  4) 登录成功后 NapCat 会把账号配置写进 app\napcat\data\config\，3001 端口
     开始监听，桥接自动连上，机器人上线。
  提示：二维码会过期，过期点页面刷新即可。
  补充：封装包在 app\napcat\data\config\ 里预置了一份通用 onebot11.json（含
  127.0.0.1:3001 正向 WebSocket 服务器），新账号登录后会自动套用，一般不用
  手动进 NapCat 网络配置；若你改了 NapCat 侧配置后 3001 不通，按第七节排查。

4.2 换机 / 新设备登录（重要，不是故障）
  换一台电脑登录同一个 QQ，腾讯风控必然触发：
    - 轻则短信验证码；重则要求扫码 + 新设备验证；
  这是腾讯的正常安全流程，不是本封装包的问题。照着页面提示做：
    - 要验证码：让手机 QQ 接收短信/安全验证；
    - 要扫码：页面有二维码就用小号手机 QQ 扫；
    - 页面提示"新设备验证"：按提示在常用设备上确认。
  完成一次后，这台机器会记住登录态，之后重启 NapCat 会自动快速登录（免扫码）。

4.3 快速登录原理与账密回退
  - NapCat 默认启动方式（启动NapCat.bat）：不带 -q 参数。首次=二维码；
    之后本地已有登录态缓存 → 自动快速登录上次的号。
  - 账密回退（启动NapCat-账密回退.bat）：把文件里 REM 注释的两行取消注释并填上
    小号 QQ 号与密码，快速登录失败时会自动尝试账密。注意：腾讯对新设备仍可能
    要求验证码/扫码，账密不是免验证通道；建议配合 WebUI 扫码兜底。
  - 看门狗重登用的启动器可在 config 里 watchdog.launcherBat 指定。

4.4 掉号 / 被挤下线（看门狗）
  桥接内置"掉号看门狗"（v2.2 同款逻辑）：
    每 30 秒探活一次 → 连续 3 次失败或 WS 断开 → 判定掉号 →
    结束 NapCat 进程树 → 3 秒后重新拉起（自动快速登录）→ 5 分钟内不重复 →
    连续 3 次仍失败则停止自动重试（防风控）并提示人工。
  安全闸：看门狗只有在【本程序运行期间成功登录过一次】后才武装——首次扫码
  阶段不会被反复杀进程打扰。
  边界：如果腾讯要求扫码/验证码而缓存票据又失效了，自动重登救不回来（腾讯
  没有无验证通道），此时请看 4.2 人工扫码即可。

五、管理台（http://127.0.0.1:3210）说明
--------------------------------------------------------
门户页：NapCat / DSH / OneBot / 桥接 四张状态卡（绿=运行 红=未运行，5 秒自动
刷新）；NapCat 与 DSH 的打开按钮；桥接看门狗最近动态；桥接最近日志。
管理面板：
  · 群白名单：文本框每行一个群号 → 保存即热生效；
  · 兴趣词 / 黑名单词：逗号或换行分隔 → 保存即热生效；
  · 回复规则：直接编辑 rules 全文（含占位符说明）→ 保存即热生效；
  · 服务控制：重启桥接 / 重启 NapCat（约 5 秒由启动器自动拉起；前提是当初用
    封装包的启动脚本启动的）；打开 NapCat WebUI（自动带令牌）/ DSH；
  · 日志查看：bridge.log / dsh.log 尾部滚动。
写配置前 server.mjs 会自动备份（bridge.config.json.bak + 带时间戳 .bak，保留 5 份）。

六、DSH（AI 服务）说明
--------------------------------------------------------
  · 数据根目录：app\dsh\home（封装包把 DSH_HOME 指到这里）——所有配置、API Key、
    会话历史都在包内，整个文件夹拷走即可换机器。
  · 首次启动自动生成 web profile（home\profiles\web），无需手动建。
  · DeepSeek API Key 填写：
      方式 A：打开 http://127.0.0.1:3080 → 设置页 → 模型/凭证 → 填 Key；
      方式 B：手动编辑 app\dsh\home\.credentials.yaml：
                version: 1
                refs:
                  DEEPSEEK_API_KEY: sk-你的Key
  · 没填 Key 时 DSH 也能起、网页也能开，只是 AI 会话不会出回复——这是预期，
    不是故障（填好 Key 即恢复）。
  · 会话与记忆：AI 按 "dsh.sessionId 前缀-群号" 每群一个会话。想让人设改动生效 /
    清空某群记忆：在 DSH 控制台删掉对应会话（或改 sessionId 前缀），桥接会在
    下一条消息时自动重建并按最新人设重新播种。

七、故障排查（对照表）
--------------------------------------------------------
  现象                                   处理
  ------------------------------------  ----------------------------------------
  管理台打不开(3210)                     看 停止全部.bat 是否误停；手动双击
                                        app\webui\启动WebUI.bat；看 logs\webui.log
  NapCat 网页版打不开/一直重试           1) 看 NapCat 窗口是否还活着（6099 是否监听）
                                        2) 关掉浏览器代理插件再试 3) 强制刷新 F5
  NapCat 启动报错/闪退                   看 NapCat 窗口文本；node-bundle 需完整（DLL
                                        全家桶缺一不可），重拷 app\napcat 目录恢复
  一直等不到 3001（OneBot 不绿）          小号没登录成功 → 回第四节扫码；
                                        登录后 NapCat 会在 data\config 写账号配置，
                                        3001 才会开；若登录了还不行，在 NapCat
                                        WebUI 网络配置确认"正向 WebSocket 3001"开着
  桥接日志出现反复"WS 未连接"            同上：等小号登录后 3001 就绪桥接自动连上
  AI 有回复但群里收不到                   看管理台日志是否"已回复"；查 3001 是否被
                                        多个实例占用（netstat -ano | findstr ":3001"
                                        数 ESTABLISHED，>1 = 重复实例，跑一次
                                        停止全部.bat 再重新启动全部.bat）
  @ 机器人没反应（怀疑"掉线"）           看管理台日志：是否有兜底提醒发出？AI 没 Key
                                        或 DSH 没起都会走兜底；确认 3080 卡片绿 +
                                        已填 API Key（第六节）
  回复出现两个 @@                     模型手写 @ 会被桥接剥掉；仍出现请检查
                                        replyPolicy.rules 是否被改成要求写 @
                                        （正确规则：禁止写 @，桥接自动加）
  改完 config 没生效                     保存了吗？JSON 格式对吗？（见下条）
  JSON 写坏 / 白名单失效                 groups 必须是 [群号1, 群号2] 同一方括号逗号
                                        分隔；逗号用半角；不要写 [a] [b] 两个数组；
                                        可删掉 bridge.config.json 让首次配置.bat
                                        重新生成，或用 .bak 备份恢复
  机器人说话太频繁 / 太少                 管理台调 maxRepliesPerMinute / interestKeywords
  DSH 网页 3080 打不开                   DSH 窗口是否活着；首次初始化几十秒请稍等；
                                        看 logs\dsh.log
  AI 回复特别慢 / 超时                    DeepSeek 官方接口波动；可把 timeouts.replyMs
                                        调大；检查 Key 余额
  NapCat 反复自动重登仍离线               腾讯要求扫码/验证码（见 4.2）；看门狗已按
                                        防风控自动停止，人工扫码后恢复
  端口被占用（6099/3001/3080/3210/34567）netstat -ano | findstr "端口" 找到 PID，
                                        确认不是别的服务后 taskkill /F /PID 该 PID，
                                        再重启；改 DSH 端口见 app\dsh\home 配置，
                                        改后记得同步改 bridge.config.json 的 dsh.baseUrl
  停止全部.bat 后还有残留窗口            手动关掉即可；顽固进程按上一条 netstat 查杀
  整个文件夹换位置/换电脑                直接拷贝整个 QQBot-Pack 文件夹即可（绿色）；
                                        DSH 首次启动会自动重建内部链接指向新位置；
                                        NapCat 换电脑登录见 4.2（会要验证）

--------------------------------------------------------
八、给"想自己折腾"的人
--------------------------------------------------------
  · 桥接是零 npm 依赖的纯 Node 22+ 脚本（app\bridge\），可直接
    node app\bridge\bridge.mjs 手动跑，加环境变量 BRIDGE_CONFIG 可指定别的配置。
  · DSH 版本升级：在 app\dsh 里执行 npm install @deepseek-ai/dsh@最新版本号
    --registry https://registry.npmmirror.com，然后重启 DSH 窗口。
  · 日志位置：logs\bridge.log（桥接，超 5MB 自动轮转 .1.log）、logs\dsh.log、
    logs\webui.log、NapCat 自身日志在 app\napcat\data\logs。
  · 所有 bat 均为 GBK 编码 + CRLF 行尾（Windows cmd 要求）。若你自己改了 bat
    导致乱码，多半是编码被改成了 UTF-8——用记事本"另存为"选 ANSI 保存回来。

--------------------------------------------------------
九、安全与合规
--------------------------------------------------------
  · 本包服务只监听 127.0.0.1。请勿自行改成 0.0.0.0 对外暴露（有安全风险）。
  · 请使用自己的 QQ 小号并遵守腾讯平台规则；机器人被风控/封号的风险由使用者
    自行承担（建议小号先"养"几天、控制发言频率）。
  · 分享包给别人前：删除 config\bridge.config.json、logs\ 内容、app\dsh\home\
    里的 .credentials.yaml（含你的 API Key）与 profiles（含你的会话）。
